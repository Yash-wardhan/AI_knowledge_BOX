  • Async by design: the API returns 202 immediately; the work runs in a FastAPI background task.
  • Statuses: pending → processing → completed | failed (shown as badges in the Library).
  • Re-ingest deletes the item's chunks first, so it's idempotent.
  • Delete item cascades to chunks (and ingestion_jobs) in the database.
  • Not yet used: ingestion_jobs rows and items.content_hash (duplicate detection).
  • Search later embeds the question with the same model and compares by cosine distance.
